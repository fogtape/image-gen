# 前置管理员登录、独立账号管理与瘦身设置追踪

日期：2026-04-29

## 结论

本轮返工采用推荐方案：**前置管理员登录 + 独立账号管理 + 瘦身设置页**。

- 进入前端先显示管理员登录页，输入管理员鉴权成功后才进入主应用。
- 登录后默认拥有全部管理权限，不再在设置、部署、账号存储等位置重复填写口令。
- “设置”和“账号管理”拆成两个入口：设置只放全局偏好和运维项；账号管理承载 API Key、ChatGPT OAuth、账号保存位置、Upstash、迁移和连接测试。
- 删除设置页里的旧默认配置表单；API 地址回到账号编辑里的“此账号的 API 地址”。
- Node / Docker 优先保存账号到服务端加密文件；云平台可配置 Upstash；未配置或不可用时继续回退浏览器缓存。
- 后台任务轮询如果拿到上游明确错误，会直接展示真实错误，不再伪装成连接波动反复重试。

## 方案取舍

### 方案 A：前置登录页 + 主应用全权限（已采用）

优点：最接近 metapi 的心智模型；新用户先登录再配置，权限边界清楚。账号、部署、存储都复用同一个管理员会话。

### 方案 B：保留主应用可见，只在敏感操作弹登录

优点：轻量；缺点是用户仍然不知道管理员鉴权该在哪里填，且配置路径会继续分散。

### 方案 C：每个敏感区各自填鉴权

优点：改动最小；缺点是正是当前混乱来源，已排除。

## 界面边界

### 管理员登录

- 入口：页面首屏 `#adminLoginShell`。
- 表单：`#adminGateTokenInput` + `#adminGateLoginBtn`。
- 成功后：持久化管理员会话，隐藏登录页，显示 `#mainAppShell`。
- 退出：顶部“退出”按钮清理管理员会话并回到登录页。

### 设置

只保留五组：

1. 生成：尺寸、质量、格式、数量、代理开关。
2. 外观：提示词增强、水印。
3. 图片存储：图片历史开关、存储状态、清理操作。
4. 部署：平台校验、同步环境变量、触发重新部署。
5. 备份：安全导出、完整加密导出、导入。

不再放账号列表、OAuth 登录、账号存储配置，也不再出现旧默认配置表单。

### 账号管理

独立弹窗 `#accountOverlay`：

1. API Key 账号：添加 / 编辑 / 删除 API Key 账号；API 地址在账号编辑中填写。
2. ChatGPT 登录：OAuth 登录、手动回填授权码、已登录账号列表。
3. 保存位置：服务端文件、Upstash、浏览器 fallback、迁移当前浏览器账号、测试账号存储、测试当前账号连接。

## 数据保存优先级

1. 已管理员登录且服务端账号存储可写：优先写服务端。
2. Node / Docker：默认服务端加密文件 `data/accounts.enc.json`，加密 key 来自环境变量或 `config/.account-store-key`。
3. 云平台：配置 Upstash REST URL / Token / 加密 Key 后写 Upstash。
4. 不支持、未配置或测试失败：保留旧逻辑，保存到当前浏览器缓存。
5. 浏览器副本保留作为 fallback，服务端同步失败不阻断生成。

## 错误处理

后台任务轮询区分两类错误：

- 网络超时、临时 5xx 且没有明确错误正文：允许按后台连接波动短暂重试。
- 后端已经返回 `failed` 状态，或轮询接口返回 `error/message`：标记为终止性后台任务失败，直接把上游真实错误交给统一错误弹窗展示。
